# M3: bounded agent loop and deterministic guardrails

The implementation uses OpenAI, as requested. Credentials stay in the ignored local
`.env`; `.env.example` contains an empty placeholder. Live verification results are
recorded below. M4 has not started.

## Run

After adding your key locally:

```bash
cd api
../.venv/bin/python -m agent.loop cycle_0 --corridor US-NG
../.venv/bin/python -m agent.loop collector_0 --corridor US-NG
../.venv/bin/python -m agent.loop shared_0 --corridor US-NG
../.venv/bin/python -m agent.loop ajo_0 --corridor US-NG
```

Each command writes a new case to the configured graph and prints JSON events, ending
with the stored decision. `OPENAI_MODEL` defaults to `gpt-4.1-mini`; `--model` overrides
it. The default is configurable, not an assertion of account access. A missing key
fails before opening a case. Do not paste credentials into chat or commit `.env`.

Tests without a model key:

```bash
CORRIDOR_LIVE_TESTS=1 ../.venv/bin/python -m unittest tests.test_agent -v
CORRIDOR_LIVE_TESTS=1 ../.venv/bin/python -m unittest discover -s tests -v
```

These use a disposable real FalkorDB graph and **scripted model responses**. The
four-pattern test exercises the CLI entrypoint and persistence; it does not establish
live-model detection quality. No scripted provider is exposed as the production CLI.
OpenAI adapter tests mock the SDK and verify function-call/result wiring and rejection
of invalid responses. Temporary graphs are deleted; the demo graph remains unchanged.

## Execution and data flow

- Open the case and call `prior_cases` first, excluding the new case. A historical
  FREEZE sets a deterministic risk floor of 0.7; it is not independent freeze evidence.
- Load account metadata (pool IDs and latest transfer timestamp) from a fixed graph
  query. The agent never reads `ground_truth.json`. The suggested 48-hour window derives
  from transfer timestamps, not today's clock, so the fixed synthetic seed remains usable.
- The model chooses among nine read tools or `finish_investigation`. It cannot call
  writes, ingestion, arbitrary query text, or bypass the mandatory reads. Reserve two
  final steps for `corridor_context` and `precedents`: at most twelve analytical tool
  calls total, including the initial memory lookup. Bootstrap, citation resolution,
  persistence, and deterministic audit notes are not analytical steps.
- After each result, resolve only IDs drawn from known result fields (plus an established
  starting account) against the graph. The model receives this allowlist and returns a
  one-sentence interpretation plus cited IDs. Unsupported citations are removed, recorded,
  and force MONITOR. Empty results are persisted too. Interpretation requests contain
  only the current native function call and result, excluding earlier findings to reduce
  confusion between an empty result and an earlier observation.
- Retrieve corridor context, validate the model's selected policy against returned IDs,
  then retrieve current precedents. The verdict's policy must match that lookup. Validate
  verdict shape, finite risk, members, lead, and precedent before writing the case.
- Persist raw tool results, JSON parameters, interpretations, citation rejections, and
  interpretation source on Findings. Store proposed/final verdict details, rationale,
  guardrail reasons, and cap status on the Case. Deterministic notes use `tool='guardrail'`.
  The event callback is ready for M5; this milestone does not implement HTTP/SSE.

The provider uses the [Responses function-calling interface](https://developers.openai.com/api/docs/guides/function-calling)
with strict schemas, one function call per response, `store=false`, a 45-second request
timeout, and automatic retries disabled. Graph data is serialized inside delimited
untrusted-data blocks, with angle brackets escaped so document text cannot close the
block. This is a prompt/data boundary, not a claim that prompt injection is solved.

## Code-enforced verdict rules

`agent/guardrails.py` requires two distinct positive evidence tools citing the **same
account included in the decision** before FREEZE is permitted. Repeated calls to one
tool do not count twice. Positivity is derived from returned graph evidence:

| Tool | Eligible positive evidence |
|---|---|
| `circular_flows` | A chronological, skimming cycle passed the fixed query |
| `shared_identifiers` | At least three distinct peers, beyond the two-person family control |
| `fan_in` | At least twelve distinct senders in its bounded window |
| `ajo_payout_pattern` | Consecutive payouts plus shared-device evidence |
| `link_to_known_bad` | A nonzero path to a historical FREEZE account |

These are synthetic demo rules, not regulatory thresholds. Algorithms, company metadata,
prior-case retrieval, empty/error results, and uncited findings never count as independent
positive evidence. These checks establish structural corroboration and valid citation IDs;
they do not semantically prove every sentence the model writes. An unsupported FREEZE is
downgraded to MONITOR with a persisted explanation. Risk is model-proposed except for the
historical-FREEZE floor. A structural-only shared-device case can remain MONITOR.

## Failure behavior and review

- Unknown account: memory is checked first, then a deterministic error finding is written
  and the case closes CLEAR with `error='unknown_account'`. This is an input error, not a
  compliance clearance, and requires no model call within the loop.
- Invalid tool selection, model timeout/refusal/malformed output, invalid citations, or
  invalid tool parameters: record the issue and prevent automatic CLEAR/FREEZE; close
  MONITOR using available valid grounding.
- Missing/mismatched/stale company references: close an **unrouted** MONITOR with
  `error='review_required'`; never fabricate an assignee or policy link.
- Step cap: stop exploration, complete reserved grounding reads, decide with existing
  evidence, and persist `step_cap_reached=true`.
- Database failure: return a sanitized error with the case ID. A partially written case
  may remain open; the code never claims a successful close if a database call failed.

Inspect any case using `investigation_audit.cypher`, `case_evidence.cypher`, and
`case_state.cypher`, each with `CYPHER case_id='the_returned_case_id'`. The audit query
includes raw results and deterministic notes; `case_evidence` reconstructs actual CITES.
