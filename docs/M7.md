# M7: cross-account case memory

The memory demonstration runs two investigations with separate loop instances.
The first investigates `collector_0`. The second investigates a different account
selected from the first case's persisted `INVOLVES` relationships. Its first tool
must be `prior_cases`, and its stored raw result must contain the first case ID.
No fixture label or injected model answer is used to establish that match.

## Run

With the existing local credentials configured:

```bash
cd api
../.venv/bin/python -m data.check_memory --output ../docs/m7-live-verification.json
```

This creates two real cases, invokes OpenAI, and retains their history. It does not
reset the graph. If the first investigation records no other member, the command
fails explicitly rather than inventing a relationship. The output includes both
case paths for the workspace at http://localhost:3001. Verdicts can vary.

For the repeatable regression check (real disposable FalkorDB graph, scripted
model, no OpenAI calls):

```bash
cd api
CORRIDOR_LIVE_TESTS=1 ../.venv/bin/python -m unittest tests.test_agent.AgentGraphTests.test_second_account_recalls_first_case_on_step_one -v
```

The regression also checks that historical FREEZE raises risk to at least 0.7 but
cannot, by itself, justify freezing the second account.

## Explain it live

1. Open the first saved case and inspect its members and evidence.
2. Open the second saved case. Its account differs from the first flag.
3. Expand Technical details on the first finding, “Review account history”. The
   raw result includes the first case's ID, verdict, role, and key findings.
4. Explain the traversal: Account ← INVOLVES — Case → HAS_FINDING → Finding.
   The lookup excludes the newly opened case. Memory is in FalkorDB, not a chat
   transcript. The first case need not have a FREEZE verdict to be remembered.

In FalkorDB Browser, paste `api/queries/prior_cases.cypher` with parameters:
`account_id` = the report's `second_account`; `exclude_case_id` = its
`second_case.case_id`. Use `case_evidence.cypher` and `investigation_audit.cypher`
with `case_id` = that same second case to inspect the persisted step-one evidence.
The query text remains fixed and parameterized; no new query or verdict rule was
needed for M7.

The queue still shows the original four synthetic flags. This demo command is the
explicit entry point for the second account, and its saved investigation opens in
the existing workspace. It does not fabricate a new queue flag.
