# M8: local MCP tools

Corridor exposes its 12 fixed read tools through the official Python MCP SDK's
FastMCP server over stdio. The adapter calls `agent.tools.CorridorTools`; all Cypher
still lives in `api/queries/`. Tool discovery works before database connection.
Tool schemas bound identifiers, list lengths, timestamps, amounts, and cycle depth.
Database failures return credential-free tool errors.

## Install and connect

```bash
.venv/bin/python -m pip install -r api/requirements.lock.txt
cd api
../.venv/bin/python -m mcp_server
```

A stdio server waits for an MCP client, so running this command alone does not show
a web page. Configure a client to launch it, using your absolute checkout path:

```json
{
  "mcpServers": {
    "corridor": {
      "command": "/absolute/path/corridor/.venv/bin/python",
      "args": ["-m", "mcp_server"],
      "cwd": "/absolute/path/corridor/api"
    }
  }
}
```

This is a common client configuration shape; adapt the server entry to your
client's format. The server loads the ignored repository `.env` through the same
database connector as the application. No credentials belong in the client JSON.
No OpenAI key is required for read tools. Protocol messages use stdout; diagnostic
logging uses stderr. No network listener, hosted MCP endpoint, or client account
configuration is installed by this milestone.

## Tools and boundaries

- Transaction evidence: `shared_identifiers`, `circular_flows`, `fan_in`,
  `ajo_payout_pattern`, `ring_communities`, `connected_cluster`, `collector_rank`,
  `link_to_known_bad`.
- Company context: `corridor_context`, `precedents`, `who_knows`.
- Persisted memory: `prior_cases`.

Each tool advertises read-only, non-destructive annotations and returns structured
results. Annotations describe behavior; enforcement comes from the explicit
registration allowlist and existing read-query functions.

**Correction to the original “same tools” sketch:** the three low-level receipt
writers (`open_case`, `record_finding`, `close_case`) are deliberately not exposed.
They do not independently enforce the agent loop's evidence/verdict guardrails.
Use the existing API or CLI investigation flow to create cases. There is no
arbitrary Cypher executor, graph reset tool, or alternate verdict-writing path.
Shared devices and graph algorithm scores alone do not establish fraud.

The module is named `mcp_server`, not `mcp`, to avoid shadowing the SDK. The pinned
`mcp==1.30.0` uses the v1 maintenance API requested by the README's FastMCP design;
it is not claimed to be the latest major SDK. See the official
[v1 documentation](https://py.sdk.modelcontextprotocol.io/v1/) for compatibility.

## Verification

```bash
cd api
../.venv/bin/python -m unittest tests.test_mcp -v
# Real stdio subprocess + SDK client + configured FalkorDB; no writes or model calls:
../.venv/bin/python -m data.check_mcp
```

The unit tests check discovery, lazy connection, bounded inputs, fixed read-query
routing, sanitized database errors, and rejection of write/query/reset names.
The protocol verifier initializes a real MCP session, discovers the exact read
allowlist, invokes all 12 tools, and checks that an unexposed write and invalid
cycle depth return tool errors. Fixture parameters are used only by this verifier,
not by the MCP server. Results are saved in `m8-live-verification.json`.

## Results — October 17, 2026

11 tests passed in 0.034 seconds: 4 MCP adapter tests and 7 existing guardrail/model
adapter checks. The real stdio client negotiated protocol `2025-11-25` and called
all 12 tools successfully. Every call returned seeded evidence; explicit assertions
confirmed the five-transfer cycle, 12-sender fan-in, corridor lead, and current
precedent. Both invalid-depth and unexposed-write calls returned tool errors.
Dependency consistency and Python compilation passed.
