# M5: API and investigation streaming

Run the local API with one worker:

```bash
cd api
../.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000
```

Interactive endpoint documentation is at `http://127.0.0.1:8000/docs`.
FalkorDB and OpenAI settings come from the ignored repository `.env`. The API uses
FastAPI's [lifespan](https://fastapi.tiangolo.com/advanced/events/) and
[streaming response](https://fastapi.tiangolo.com/advanced/stream-data/) interfaces.
Blocking database/model work runs off the event loop.

## Requests

```bash
curl http://127.0.0.1:8000/flags
curl -X POST http://127.0.0.1:8000/investigate/cycle_0 \
  -H 'Content-Type: application/json' -d '{"corridor":"US-NG"}'
# Substitute the returned case ID below:
curl -N http://127.0.0.1:8000/cases/CASE_ID/stream
curl http://127.0.0.1:8000/cases/CASE_ID
curl http://127.0.0.1:8000/cases/CASE_ID/subgraph
curl http://127.0.0.1:8000/accounts/cycle_0/history
```

POST returns HTTP 202 with `case_id` and `stream_url` after saving the open case.
The optional body selects US-NG (default) or NG-US. Model configuration failure
returns 503 before creating a case. Invalid request fields return 422. Duplicate
active investigations for the same account return 409; at most four run at once.

The seed flags accounts, not individual transfers. `/flags` returns those four
persistent demo candidates with their latest adjacent transfer, corridor US-NG,
prior-case badge, and active-case count. Historical cases do not erase seed flags,
so the returning-account memory demonstration remains possible. This is an explicit
adaptation of the README's “flagged transfers” label to the actual seed model.

The case response contains saved case properties (including verdict), raw findings,
routing, citation evidence, and the cited subgraph. The subgraph contains up to 500
cited nodes and 1,000 edges between those nodes, with `possibly_truncated` when a
limit is reached. These are graph relationships, not a claim that every displayed
edge independently supports the verdict. Unknown cases return 404; unknown account
history is empty. An unknown-account investigation preserves M3's explicit error
closure rather than representing it as a successful compliance clearance.

## Stream and persistence

Each SSE frame has an integer `id`, named `event`, and JSON `data`. Events include
`opened`, `finding`, `guardrail`, `closed`, `error`, and terminal `end`. Heartbeat
comments are sent every ten seconds while waiting. Close the browser EventSource
on `end`. Reconnect using `Last-Event-ID` or `?after=N` to replay later buffered
events. Disconnecting a viewer does not cancel the investigation.

Event buffers and active jobs belong to one process; use exactly one worker. Up to
100 recent jobs are retained for exact replay. After restart or buffer eviction,
the stream emits a durable `snapshot` from FalkorDB followed by `end`; it does not
pretend to reproduce the original event sequence. An open snapshot without an
active worker needs inspection before retrying. Unexpected worker failures emit a
sanitized error; partial cases may remain open. Graceful shutdown waits for workers.
This milestone is a local demo service, not a durable distributed job queue.

## Explicit reset

`POST /admin/reset` is disabled unless `CORRIDOR_ADMIN_TOKEN` is set in local `.env`.
Send that value in `X-Admin-Token` and JSON `{"confirm_graph":"corridor"}` (or the
actual configured graph name). Reset is rejected during active investigations or
another reset. It rebuilds only that graph using seed 42 and clears event buffers.
It deletes saved demo investigations as part of the explicit reset request.
Tests reset only a uniquely named disposable graph; the configured demo graph is
not reset during M5 verification.

A real localhost HTTP client started `collector_0` using the configured OpenAI
provider and remote FalkorDB. It received 13 SSE events through `end`, then verified
the saved case, history, and subgraph (18 nodes, 13 edges). Case ID:
`case_9993946814ce4c43b0ef37e0b34ebfb1`.

which is outside the permitted CITES labels; the guardrail rejected that citation
and prevented automatic CLEAR/FREEZE. Prior FREEZE history also enforced the 0.7
risk floor. This demonstrates the error path over HTTP, not a claim of perfect
model interpretation. Full events and persisted output are in
