# M2: fixed query tools

M2 implements 15 callable tools in `agent.tools.CorridorTools`. `open_case` is the
fifteenth tool: the original README listed fourteen names but required case creation
in its agent loop. No LLM loop, model tool schemas, verdict guardrails, API, or MCP
server is introduced in this milestone.

## Run and inspect

From the repository root:

```bash
cd api
CORRIDOR_LIVE_TESTS=1 ../.venv/bin/python -m unittest tests.test_queries -v
../.venv/bin/python -m data.check_tools
```

The first command loads a unique disposable graph, adds boundary fixtures, tests read
and write behavior, then deletes only that graph. The second command runs all twelve
read-only tools against the configured demo graph and prints JSON results. It does
not open cases or change the demo. To run both milestones' complete suite:

```bash
CORRIDOR_LIVE_TESTS=1 ../.venv/bin/python -m unittest discover -s tests -v
```

Python usage (from `api/`):

```python
from db import connect
from agent.tools import CorridorTools

tools = CorridorTools(connect())
rows = tools.circular_flows('cycle_0', max_hops=5)
print(rows)
```

Read methods return lists of JSON-compatible dictionaries. Write methods return a
receipt dictionary and reject unmatched case/reference requirements with `ValueError`.
`call(name, **params)` only permits the fifteen named tools, not ingestion or arbitrary
query execution. Raw query helpers are internal application utilities, not model tools.
All Cypher is loaded from static files in `api/queries/`; parameters never become query
text. Numeric/list bounds reject invalid values before contacting the database.

## Query review map

Every name below links to its executable source. In Browser, select `corridor`, paste
the file contents, and prepend its parameter header. The headers below are for reads.
For writes, use a disposable graph; the integration test demonstrates the complete
open → record → close sequence with generated IDs and epoch-second timestamps.

| Tool / query | Browser parameter header or write inputs | What to explain |
|---|---|---|
| [shared_identifiers](../api/queries/shared_identifiers.cypher) | `CYPHER account_id='cycle_0'` | Two-hop shared device/phone; returns both edge IDs and each peer |
| [circular_flows](../api/queries/circular_flows.cypher) | `CYPHER account_id='cycle_0' max_hops=5` | Four fixed 2–5-hop branches, distinct accounts, ordered/skimming transfers within 72h |
| [fan_in](../api/queries/fan_in.cypher) | `CYPHER account_id='collector_0' since=1792065599 max_amount=500.0` | Distinct senders, explicit transfer counts and totals within 48h |

| [ring_communities](../api/queries/ring_communities.cypher) | `CYPHER account_ids=['cycle_0','cycle_1','cycle_2','cycle_3','cycle_4']` | Label propagation over accounts/devices/phones; filter requested accounts after computation |
| [connected_cluster](../api/queries/connected_cluster.cypher) | `CYPHER account_id='cycle_0'` | WCC uses only identifier relationships; money transfers cannot merge components |
| [collector_rank](../api/queries/collector_rank.cypher) | `CYPHER account_ids=['mule_0','mule_1','collector_0']` | PageRank over all account transfers, then filter; rank is not a risk score |
| [link_to_known_bad](../api/queries/link_to_known_bad.cypher) | `CYPHER account_id='mule_1'` | Unweighted bidirectional SPpaths, maximum six edges, against historical FREEZE members |

| [who_knows](../api/queries/who_knows.cypher) | `CYPHER pattern='fan_in_mule'` | Case → precedent → employee experience |
| [prior_cases](../api/queries/prior_cases.cypher) | `CYPHER account_id='mule_0' exclude_case_id=''` | Ordered findings; exclude the just-opened case in M3 |

a separate static query selected by the same tool. Inspect persisted results with
[case_evidence](../api/queries/case_evidence.cypher) and
[case_state](../api/queries/case_state.cypher), both parameterized by `case_id`.

## Verified compatibility and behavior

- The deployed graph rejected undirected `shortestPath`. The documented
  [SPpaths procedure](https://docs.falkordb.com/algorithms/sppath) supports
  `relDirection: 'both'`. With no weight property, live tests verify hop-minimizing
  paths, including mixed transfer/identifier directions and the six-hop cutoff.
- Closed variable-length path projections in M1 returned unexpected ordering. The
  circular tool uses explicit aliases in four static branches. Each branch returns
  at most ten rows; the Python wrapper sorts the bounded result and returns at most
  ten overall. `max_hops` is enforced, not ignored. No runtime query construction occurs.
- `fan_in` treats `since` as the exclusive start of a 48-hour interval and its end
  as inclusive. Amounts must be strictly below `max_amount`. An existing account
  with no matches returns zero counts; an unknown account returns no rows.
- Ajo evidence is scoped by `pool_id`, `purpose='ajo_payout'`, and consecutive rounds.
  Shared devices are additional evidence; repeated recipients can be returned without
  device sharing. Neither family device sharing nor a community assignment is itself
  a fraud verdict.
- [PageRank](https://docs.falkordb.com/algorithms/pagerank),
  [WCC](https://docs.falkordb.com/algorithms/wcc), and
  [label propagation](https://docs.falkordb.com/algorithms/cdlp) execute in FalkorDB.
  Algorithms run globally over their label/relationship filters. Community IDs are
  graph-local and may vary; tests assert member coverage rather than exact IDs.
- Writes use epoch seconds consistently. Missing citations, missing members, stale
  decisions, wrong corridor leads, and attempts to modify closed cases are rejected.
  Citation existence is checked here; whether a model's claim is supported by a tool
  result belongs to M3. `close_case` does not enforce the two-independent-findings
  FREEZE rule: M3 must apply deterministic guardrails before calling it.
- Unknown-account early CLEAR closure and other agent failure handling remain M3 work.
  The normal M2 closure requires nonempty members and valid company references.

## Verification record

**26 tests passed, zero skipped, in 66.559 seconds** for the combined M1/M2 suite.
This includes fourteen M2 tests (ten live behavior tests and four local tool-contract
tests). The live fixtures and temporary write cases were cleaned up. Read-only demo
results are saved in [m2-verification.json](m2-verification.json).

Internal relationship IDs in shared-identifier/shortest-path results are valid for the
current graph only and change after reset. Transfer IDs and natural node IDs are stable
in the seeded data. No automatic enforcement of an analyst's Browser review is claimed.
